# 医药 B2B ERP · M1 验收清单（可执行）

> 本清单供主窗口验收后端时直接执行。所有命令在 `Git Bash` / `bash` 环境运行。
> 前置：后端已按 `backend/run.sh` 启动（JDK17，端口 8080），Flyway 迁移完成。
> 统一响应约定：成功 `{"code":200,"message":"success","data":...}`。

---

## 0. 环境准备

```bash
# 定义基础变量（可整段复制到终端）
BASE=http://localhost:8080/api
```

### 0.1 健康检查（无需 token）

```bash
curl -s $BASE/health
```

**预期结果：**
```json
{"code":200,"message":"success","data":{"status":"UP","service":"pharma-erp","java":"17.0.21"}}
```
> `java` 显示 `17.0.21`（或 17.x）即确认跑在 JDK17 上。

---

## 1. 认证

### 1.1 登录成功，获取 token

```bash
curl -s -X POST $BASE/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'
```

**预期结果：**
```json
{"code":200,"message":"success","data":{"token":"<JWT字符串>","user":{"id":1,"username":"admin","realName":"管理员","roles":["ADMIN"]}}}
```

提取 token 存变量（**推荐用 jq**）：
```bash
TOKEN=$(curl -s -X POST $BASE/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | jq -r '.data.token')
echo $TOKEN   # 确认非空
```

> 若环境无 `jq`：手动复制返回 JSON 中 `data.token` 的值，然后执行 `TOKEN='<粘贴的token>'`。

### 1.2 登录失败（密码错误）

```bash
curl -s -X POST $BASE/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"wrong"}'
```

**预期结果：** `code != 200`（如 401），`"data":null`，message 含认证失败信息。

### 1.3 获取当前用户（带 token）

```bash
curl -s $BASE/auth/me -H "Authorization: Bearer $TOKEN"
```

**预期结果：**
```json
{"code":200,"message":"success","data":{"id":1,"username":"admin","realName":"管理员","roles":["ADMIN"]}}
```

### 1.4 无 token 访问受保护接口 → 401（红线）

```bash
curl -s -o /dev/null -w "%{http_code}\n" $BASE/products
```

**预期结果：** 输出 `401`（HTTP 状态码，非 200）。

## 2. 商品 product（字段：code, genericName, tradeName, approvalNo, dosageForm, spec, manufacturer, rxCategory, storageCond, firstAuditStatus, status）

### 2.1 新增商品

```bash
curl -s -X POST $BASE/products \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "code":"P-001",
    "genericName":"阿莫西林胶囊",
    "tradeName":"阿莫仙",
    "approvalNo":"国药准字H20012345",
    "dosageForm":"胶囊剂",
    "spec":"0.25g*24粒",
    "manufacturer":"某制药厂",
    "rxCategory":"RX",
    "storageCond":"阴凉",
    "firstAuditStatus":"PENDING",
    "status":"ACTIVE"
  }'
```

**预期结果：** `code=200`；`data` 含生成的 `id`（数字）与 `createdAt`；`firstAuditStatus` 默认 `PENDING`。

记录商品 id（后续用）：
```bash
PID=$(curl -s -X POST $BASE/products \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"code":"P-001","genericName":"阿莫西林胶囊","tradeName":"阿莫仙","approvalNo":"国药准字H20012345","dosageForm":"胶囊剂","spec":"0.25g*24粒","manufacturer":"某制药厂","rxCategory":"RX","storageCond":"阴凉","firstAuditStatus":"PENDING","status":"ACTIVE"}' \
  | jq -r '.data.id')
echo $PID
```

### 2.2 商品列表（分页）

```bash
curl -s "$BASE/products?keyword=&page=1&size=20" \
  -H "Authorization: Bearer $TOKEN"
```

**预期结果：** `code=200`；`data` 形如 `{"records":[...],"total":1,"page":1,"size":20}`。

### 2.3 商品关键字搜索

```bash
curl -s "$BASE/products?keyword=阿莫西林&page=1&size=20" \
  -H "Authorization: Bearer $TOKEN"
```

**预期结果：** `data.records` 仅含通用名/商品名匹配"阿莫西林"的记录，`data.total` 相应变化。

### 2.4 商品详情

```bash
curl -s $BASE/products/$PID -H "Authorization: Bearer $TOKEN"
```

**预期结果：** `code=200`；返回 id 为 `$PID` 的完整字段。

### 2.5 更新商品

```bash
curl -s -X PUT $BASE/products/$PID \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"tradeName":"阿莫仙（新）","spec":"0.25g*30粒"}'
```

**预期结果：** `code=200`；随后 `GET /api/products/$PID` 中 tradeName/spec 已更新。

### 2.6 编码唯一性（重复 code 应失败）

```bash
curl -s -X POST $BASE/products \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"code":"P-001","genericName":"重复编码测试"}'
```

**预期结果：** `code != 200`，message 提示编码重复。

### 2.7 必填字段校验（缺 genericName 应失败）

```bash
curl -s -X POST $BASE/products \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"code":"P-002"}'
```

**预期结果：** `code != 200`（400 类），message 提示 genericName 缺失。

## 6. 验收判定标准（对照 M1 验收标准）

| 检查项 | 判定依据 | 通过条件 |
|---|---|---|
| 健康检查 | §0.1 | `/api/health` 返回 UP，java 17.x |
| 登录拿 token | §1.1 | `data.token` 非空，`data.user.roles` 含角色 |
| 登录失败 | §1.2 | `code != 200`，`data=null` |
| 无 token 401 | §1.4 / §3.5 | HTTP 状态码 401 |
| 商品 CRUD | §2.1~2.7 | 增/查/改符合契约，唯一性与必填校验生效 |
| 供应商 CRUD | §3.1~3.4 | 增/查/改符合契约 |
| 客户 CRUD | §4.1~4.4 | 增/查/改符合契约 |
| 仓库 CRUD | §5.1~5.3 | 增/查/改符合契约 |
| Flyway 完整 | 后端日志/`flyway_schema_history` | 迁移记录完整，无校验错误 |

> 全部通过即 M1 后端验收通过；任一 P0 项失败（如 401、唯一性、必填校验）则打回修改。
